# Book Essays + `linked_book` Taxonomy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every published book in `/writing` a dedicated behind-the-book blog post, and make book pages automatically surface every post about them via a new `linked_book` taxonomy, so linking is one-directional and never drifts.

**Architecture:** Register `linked_book` as a Hugo taxonomy (mirroring the existing `linked_project`). Posts declare `linked-books: ["<book-slug>"]`; the book template (`layouts/writing/single.html`) reads the taxonomy term page for its own slug and renders those posts in the "Discussion & Related" section, deduped against the existing hand-curated `related_posts` and Hugo's fuzzy `.Related` engine. Then write 11 essays, one per book that lacks one, each backdated near its book's release.

**Tech Stack:** Hugo (static site), Go HTML templates, TOML config, Markdown content with YAML front matter.

## Global Constraints

- **No em-dashes anywhere.** A PostToolUse soul hook (`check-banned-phrases.sh`) rejects any file write containing an em-dash character. Use commas, periods, colons, or parentheses. This applies to every file in this plan (front matter, prose, this plan's own edits).
- **All Hugo builds write to `docs/`** (`publishDir = 'docs'` in `hugo.toml`). A dirty `docs/` tree after a build is normal and expected. Never gitignore `docs/`.
- **Voice reference for all prose:** `.mf/soul.md`. First person, plain, direct, pedagogical, dry humor, no clichés, no self-aggrandizement, no vanity metrics.
- **Book slug = book directory name** under `content/writing/` (e.g. `bob`, `echoes-sublime`, `the-policy`). The template derives it via `.File.ContentBaseName`. Every `linked-books` value must equal a book directory name exactly.
- **Taxonomy front-matter key is the plural `linked-books`, not `linked_book`.** Hugo populates a taxonomy from the front-matter key equal to the config's plural value (`linked_book = "linked-books"` in `hugo.toml`), exactly as `tags`/`categories` work. Using `linked_book:` in a post's front matter silently produces zero terms. Verified empirically during Task 1. (The taxonomy's config-key name is `linked_book`; the URL base and the front-matter key are `linked-books`.)
- **Do not edit generated content.** `content/papers/` and `content/publications/` are generated by the `mf` CLI. They stay linked via manual `related_posts` on book pages, never retrofitted with `linked_book`.
- **Build command:** `hugo --gc --minify` (run from repo root `/home/spinoza/github/repos/metafunctor`). Must exit 0.

## Shared Procedure: Writing One Book Essay (used by Tasks 2-12)

Every essay task follows this identical procedure. It is written out here once, in full, so any task can be executed out of order by referring to this section. Each task below supplies only its unique data: the file path, the complete front matter, and the essay's angle.

**Before writing prose:**
1. Read `.mf/soul.md` in full (the voice reference).
2. Read the book's own page `content/writing/<SLUG>/index.md` and mine its `description`, `context`, and `inspiration` front matter. That text is the seed; do not copy it verbatim, reformulate it in essay voice.

**Writing the prose (the body below the front matter):**
- Length: roughly 1,000 to 2,000 words.
- First person, in Alex's voice. This is a behind-the-book essay, not a blurb and not a sales pitch. The register is the existing post `content/post/2024-09-10-the-policy/index.md`: start from the idea the book chases, explain it so a reader learns something, and let the book be the place that idea gets dramatized.
- Open with the idea or the question, not with "I wrote a book called X."
- Teach one real concept the book is built on (the angle is given per task). Be concrete.
- Do not spoil endings or key reveals. It is fine to describe the premise and the questions.
- Include exactly one inline Markdown link to the book page, written as `[<book title>](/writing/<SLUG>/)`, placed naturally where you point the reader to the book.
- No em-dashes. No clichés ("dives into", "explores the intersection of", "at its core"). Dry, plain, honest.

**Front matter:** use the exact YAML given in the task. Do not add fields not listed.
